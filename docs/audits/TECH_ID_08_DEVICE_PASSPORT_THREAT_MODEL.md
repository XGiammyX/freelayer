# TECH-ID-08 — Device Passport Threat Model

> **Sourcing / scope caveat (read first).** This is a **documentation-only, pre-implementation** threat model for the TECH-ID-08 **Device Passport** (the additive `packages/identity/src/device-passports/` module + `DevicePassportStateV1` aggregate that TECH-ID-08 introduces per [TECH_ID_08_PRECHECK.md](TECH_ID_08_PRECHECK.md) §4). It adds **no cryptography**: no signatures, no signed or verified passport, no replay-resistant linking, no remote activation/acceptance, no QR/Capsule transport, no remote revocation, and no hardware or posture guarantee. **A local unsigned approval is not cryptographic authorization and grants no operational device authority** ([TECH_ID_08_PRECHECK.md](TECH_ID_08_PRECHECK.md) §6). Signed issuance + passport verification are **Gate F**; QR / wire transport is **Gate E**; synchronization / remote revocation are **Gate H**; endpoint protection is **external** (Secure Device / Endpoint Defense, [ADR-0012](../adr/ADR-0012-endpoint-defense-layer.md)). Structural decisions: [ADR-0013](../adr/ADR-0013-identity-firewall-architecture.md) §11 (multi-device model, "the Device Passport implies no hardware attestation"), §19 (deferred gates). Precedent reused verbatim in format: [TECH_ID_07_DEVICE_KEY_THREAT_MODEL.md](TECH_ID_07_DEVICE_KEY_THREAT_MODEL.md) (Device Key Model — the surface TECH-ID-08 attenuates). Companions: [TECH_ID_04_EPHEMERAL_IDENTITY_THREAT_MODEL.md](TECH_ID_04_EPHEMERAL_IDENTITY_THREAT_MODEL.md) (process-epoch binding, memory/null retention), [RESEARCH_ID_01_IDENTITY_THREAT_MODEL.md](RESEARCH_ID_01_IDENTITY_THREAT_MODEL.md) (broad identity catalogue). **No complete mitigation is claimed for any threat below.**

> [!IMPORTANT]
> Read the **[Explicitly NOT provided](#explicitly-not-provided-read-this)** section first. TECH-ID-08 covers one **local, non-cryptographic, unsigned** artifact and nothing more:
>
> - A **Device Passport** is *a local, unsigned approval draft asserting that one identity root would authorize one candidate device to LATER operate within an attenuated slice of that root's authority* ([ADR-0013](../adr/ADR-0013-identity-firewall-architecture.md) §11). In TECH-ID-08 it holds **no signature**, is **not** verified, is **not** transmitted, and grants **no** operational device authority. Every produced authorization record keeps `origin: "device_passport_future"`, `authorizationProofState: "not_implemented_tech_id_08_gate_f"`, `cryptographicallyAuthorized: false`, `remotelySynchronized: false`, `hardwareAttested: false` ([`devices/device-types.ts`](../../packages/identity/src/devices/device-types.ts)).
>
> **A Device Passport is not DevicePosture; a passport is not attestation; a passport is not proof-of-safety; a passport is not real-world identity. A device is not a person; a passport id is not a hardware identifier; a local unsigned approval is not cryptographic authorization; a QR code is only a transport representation; room membership does not authorize a device.** Signed issuance / verification are **Gate F**; QR / transport are **Gate E**; sync / remote revocation are **Gate H**.

## How to read this model

Each category lists a concrete **attack**, then **why it fails / residual** (the structural, policy, or gate reason the attack is blunted, and what it leaves behind), and the **control** that carries the weight. A control is one of:

| Control kind | Meaning |
| --- | --- |
| **Design** | A structural invariant / type boundary / reducer discipline the TECH-ID-08 `device-passports/` module must uphold — **attenuation-only** issuance (a passport may only narrow the approver's own scope + capabilities, never widen: reuse [`attenuateDeviceAuthorizationScopeV1`](../../packages/identity/src/devices/device-scopes.ts) + [`attenuateDeviceCapabilitiesV1`](../../packages/identity/src/devices/device-authorization-context.ts)); **candidate device ref must match** throughout a link request; **key-slot commitments immutable after approval** (empty `reserved_not_generated` slots, `algorithm: "not_selected_gate_f"`, [`devices/device-key-slots.ts`](../../packages/identity/src/devices/device-key-slots.ts)); **one pending request per request id**, **one draft per request**, **approved-once**, **terminal tombstones** ([`assertDeviceAuthorizationTransitionV1`](../../packages/identity/src/devices/device-lifecycle.ts)); **opaque non-hardware** candidate/subject refs ([`devices/device-identifiers.ts`](../../packages/identity/src/devices/device-identifiers.ts)); **memory/null** retention; **redacted** summaries; **content-free** errors ([`devices/device-errors.ts`](../../packages/identity/src/devices/device-errors.ts)). Fail-closed re-validation of a captured context before execution is [`assertDeviceAuthorizationSnapshotCurrentV1`](../../packages/identity/src/devices/device-authorization-context.ts) (the model the passport link-request / draft assertions mirror per [TECH_ID_08_PRECHECK.md](TECH_ID_08_PRECHECK.md) §3–§4). |
| **Policy** | A fail-closed decision resolved against an authentic **exact-scope** `PolicyDecision`, with issuance / linking held **future-gated** in the Policy Matrix (`identity.device_passport_future` → op `identity.device_passport`, `effect: "future_gate"`, `reasonCode: "deferred_gate"`; `identity.device_key_future` → op `identity.device_key`, same effect — [`policyMatrix.ts`](../../packages/privacy/src/policyMatrix.ts)). DevicePosture and RoomOS roles are **non-approvers**: DevicePosture may only tighten ([`device-posture.ts`](../../packages/rooms/src/policy-composition/device-posture.ts) `mayOnlyTighten: true`, `trustedForElevation: false`, "never identity, never authority"), and a `devicePosture` / `attestation` / `isOwner` / `capabilities` caller field is refused by the boundary validator's `FORBIDDEN_FIELDS` ([`identity-validation.ts`](../../packages/identity/src/identity-validation.ts)). The unavailable capabilities `identity.device.add_future` + `identity.recovery.approve_future` **deny** ([`devices/device-types.ts`](../../packages/identity/src/devices/device-types.ts) `DEVICE_UNAVAILABLE_CAPABILITIES`). |
| **Gate** | Not solvable by this module: **Gate F** (signed issuance / passport signature / verification / verification fingerprints — [ADR-0013](../adr/ADR-0013-identity-firewall-architecture.md) §19), **Gate E** (QR / Capsule / wire transport), **Gate H** (sync / distributed / remote device revocation — ADR §19), **External** (Secure Device / endpoint), **Inherent** (disclosed trade-off). |

**Code anchors used repeatedly.** Attenuation — [`devices/device-scopes.ts`](../../packages/identity/src/devices/device-scopes.ts) (`attenuateDeviceAuthorizationScopeV1` rejects `cross_root_forbidden` + `scope_widening_forbidden`; `deviceScopeContainsV1` refuses cross-root and refuses read-only→writable; **no wildcard, no multi-root, no scope inferred from a label or DevicePosture**) and [`devices/device-authorization-context.ts`](../../packages/identity/src/devices/device-authorization-context.ts) (`attenuateDeviceCapabilitiesV1` is **subset-only** — `capability_expansion_forbidden`, `unknown_capability`; `assertDeviceAuthorizationSnapshotCurrentV1` fails closed on identity mismatch, revision drift, non-operational lifecycle, unusable root, and `postureTightens: true`; every snapshot is `cryptographicallyAuthorized: false`). Capabilities — [`devices/device-types.ts`](../../packages/identity/src/devices/device-types.ts) (`DEVICE_UNAVAILABLE_CAPABILITIES` = `identity.device.add_future`, `identity.recovery.approve_future`; record carries `cryptographicallyAuthorized: false` / `remotelySynchronized: false` / `hardwareAttested: false`, `origin: "device_passport_future"`, `authorizationProofState: "not_implemented_tech_id_08_gate_f"`; `LocalDeviceSummaryV1` is `redacted` with `postureVerified: false`; `LocalDeviceRevocationResultV1` flags are **all false** for remote/erasure/key-rotation/cryptographic effects). Key slots — [`devices/device-key-slots.ts`](../../packages/identity/src/devices/device-key-slots.ts) (typed placeholder, **no** public/private bytes, no fingerprint, `algorithm: "not_selected_gate_f"`, production may create only `reserved_not_generated`) + purposes [`devices/device-key-purposes.ts`](../../packages/identity/src/devices/device-key-purposes.ts) (each purpose `*_future`; one slot = one purpose). Authority epoch — [`identifiers.ts`](../../packages/identity/src/identifiers.ts) (`IdentityAuthorityEpoch` is a **positive local counter that changes ONLY through explicit root lifecycle operations**, "a changed epoch invalidates stale drafts + future passports"; `nextIdentityAuthorityEpoch`; `IdentityLocalRevision` is **not** a timestamp / vector clock / synchronization / cryptographic continuity; `DeviceAuthorizationRef` is a future-reference brand, **never key material**) + [`identity-types.ts`](../../packages/identity/src/identity-types.ts) (`IdentityAuthorityEpochStateV1.reason` includes `administrative_reset_forbidden` — **no** administrative reset; `LocalIdentityRootLifecycleV1` includes `recovery_required` / `recovered_reverification_required` / `compromised_suspected` / `revoked_tombstone`; `PRODUCTION_ASSURANCE_STATES` bounds what can be written). Opaque refs — [`devices/device-identifiers.ts`](../../packages/identity/src/devices/device-identifiers.ts) (a `LocalDeviceRef` encodes **no** OS/hardware id, serial, advertising id, fingerprint, hostname, model, timestamp, public key, posture, or authority; injected generation only). Boundary validator — [`identity-validation.ts`](../../packages/identity/src/identity-validation.ts) (`FORBIDDEN_FIELDS` rejects `devicePosture`, `deviceSafe`, `deviceFingerprint`, `hardwareId`, `attestation`, `publicKey`, `privateKey`, `secretKey`, `seed`, `isOwner`, `isAdmin`, `permissions`, `capabilities`, …; `assertExactKeys` refuses mass-assignment; content-free `IdentityValidationError`). Errors — [`devices/device-errors.ts`](../../packages/identity/src/devices/device-errors.ts) (`DevicePassportUnavailableError` code `device_passport_unavailable`; `DevicePostureAuthorityError` code `device_posture_authority`; `HardwareIdentifierForbiddenError`; `DeviceKeyMaterialForbiddenError`; `SAFE_DEVICE_REJECTION` — codes + static generic messages only). DevicePosture boundary — [`policy-composition/device-posture.ts`](../../packages/rooms/src/policy-composition/device-posture.ts) (`mayOnlyTighten: true`, `trustedForElevation: false`, `providerIntegrated: false`; `at_risk` always overrides higher claims; `managed_bunker` is only a posture value, never authority; `check:no-secure-device-core-implementation`).

Per [TECH_ID_08_PRECHECK.md](TECH_ID_08_PRECHECK.md) §4, TECH-ID-08 introduces an additive `device-passports/` module and a separate, current-process memory/null `DevicePassportStateV1` aggregate, reusing the TECH-ID-07 device surface (scopes, capabilities, key-slot placeholders, `DeviceAuthorizationSnapshotV1`) and the TECH-ID-08 authority-epoch primitives already present in [`identifiers.ts`](../../packages/identity/src/identifiers.ts) + [`identity-types.ts`](../../packages/identity/src/identity-types.ts). The link-request / draft assertions named below (`assertDeviceLinkRequestCurrentV1`, `assertDevicePassportDraftCurrentV1`) and the `LocalDevicePassportRevocationResultV1` result are the invariants that module **must** uphold; they mirror the fail-closed re-validation and all-false honesty flags the Device Key Model already ships. The Device Authorization record stays authoritative in the Identity Firewall; a passport is never a second source of truth.

## 1. Unauthorized issuance

The crown-jewel risk: a passport that grants operational device authority without an authentic, exact-scope root approval — or that a non-approver (UI, RoomOS role, DevicePosture, a device label, a test issuer) is treated as one.

| Attack | Why it fails / residual | Control |
| --- | --- | --- |
| **UI marks a passport valid** (client flips a draft to authorized) | A local unsigned approval grants **no** operational authority: every produced record is `cryptographicallyAuthorized: false`, `authorizationProofState: "not_implemented_tech_id_08_gate_f"`, `origin: "device_passport_future"` ([`devices/device-types.ts`](../../packages/identity/src/devices/device-types.ts)); authority/secret caller fields are refused (`assertExactKeys` + `FORBIDDEN_FIELDS`, [`identity-validation.ts`](../../packages/identity/src/identity-validation.ts)). Residual: a real signed "valid" state is Gate F — the guarantee is "no authorized state is producible," not "issuance is signed." | **Design** (no caller-set authorization) + **Gate F** |
| **RoomOS owner role issues a passport** (a room role mints device authority) | RoomOS roles are **non-approvers**: identity never imports `@freelayer/rooms`, no room capability mints an identity device authorization, and issuance is future-gated (`identity.device_passport_future` = `future_gate`, [`policyMatrix.ts`](../../packages/privacy/src/policyMatrix.ts)). Residual: none from this vector by construction. | **Policy** (issuance future-gated; role ≠ approver) |
| **DevicePosture issues or validates a passport** (a "hardened" signal approves) | DevicePosture is a **non-approver** environment attribute — `mayOnlyTighten: true`, `trustedForElevation: false`, "never identity, never authority" ([`device-posture.ts`](../../packages/rooms/src/policy-composition/device-posture.ts)); a `devicePosture` caller field is refused ([`identity-validation.ts`](../../packages/identity/src/identity-validation.ts)) and `DevicePostureAuthorityError` names the rejection ([`devices/device-errors.ts`](../../packages/identity/src/devices/device-errors.ts)). Posture can only deny, never approve. Residual: none — posture cannot grant. | **Policy** (posture tightens only; never approves) |
| **A device label grants approval** ("owner-laptop" reads as an approver) | A label carries `authority: "none"`, `postureEvidence: false`, `visibility: "local_only"` ([`devices/device-types.ts`](../../packages/identity/src/devices/device-types.ts) `LocalDeviceLabelV1`) and is never an approval input; scope is never inferred from a label ([`devices/device-scopes.ts`](../../packages/identity/src/devices/device-scopes.ts)). Residual: text can still *say* "owner" — it is never read as authority. | **Design** (`authority: "none"` label) |
| **A test issuer enters production** (a fixture approves a real passport) | The signed/verified issuer states `issued_future_signed` / `accepted_future_verified` are **not constructible in production**; production may write only the unsigned placeholder, and a new bypass guard + tests enforce it ([TECH_ID_08_PRECHECK.md](TECH_ID_08_PRECHECK.md) §6), mirroring the TECH-ID-07 single-bootstrap guardrail. Residual: fixtures must never be linked into production paths — a disclosed test-hygiene obligation. | **Design + Policy** (no producible signed state; guard + tests) |
| **A generic object patch changes passport status** (mass-assignment flips a flag) | There is **no** generic patch: commands are exact-shape (`assertExactKeys`), dangerous + authority keys reject (`FORBIDDEN_FIELDS`, [`identity-validation.ts`](../../packages/identity/src/identity-validation.ts)), and status changes flow only through explicit lifecycle transitions ([`assertDeviceAuthorizationTransitionV1`](../../packages/identity/src/devices/device-lifecycle.ts)). Residual: none from this vector by construction. | **Design** (no generic patch; explicit transitions) |
| **A restricted device issues broader authority** (a narrowed device approves a wider passport) | Issuance is **attenuation-only** against the approver's own current record — `attenuateDeviceAuthorizationScopeV1` rejects any widening ([`devices/device-scopes.ts`](../../packages/identity/src/devices/device-scopes.ts)); a `restricted_local` approver can only re-narrow, never re-expand ([`devices/device-lifecycle.ts`](../../packages/identity/src/devices/device-lifecycle.ts)). Residual: real signed delegation semantics are Gate F. | **Design** (attenuation-only) + **Gate F** |

## 2. Scope + capability escalation

A passport must never grant more than the approver holds. Every path that widens scope, re-expands capabilities, crosses roots, or introduces delegation is an attack.

| Attack | Why it fails / residual | Control |
| --- | --- | --- |
| **Candidate requests root-wide scope** (a narrow approver hands out `identity_root`) | `deviceScopeContainsV1` returns false unless the approver's scope is equal-or-wider; `attenuateDeviceAuthorizationScopeV1` rejects `scope_widening_forbidden` ([`devices/device-scopes.ts`](../../packages/identity/src/devices/device-scopes.ts)). A `persona`/`room`/`read_only` approver can never emit `identity_root`. Residual: this is a structural-metadata invariant, not a signed capability proof (Gate F). | **Design** (attenuation-only) + **Gate F** |
| **Requested scope exceeds the approver** (any widening) | Monotonic containment: widening, incomparable, or cross-root transitions reject ([`devices/device-scopes.ts`](../../packages/identity/src/devices/device-scopes.ts) `validateDeviceAuthorizationScopeV1` + `deviceScopeContainsV1`). Residual: none from this vector by construction. | **Design** (monotonic narrowing) |
| **Read-only becomes writable** (a read-only slice yields mutation authority) | `deviceScopeContainsV1` explicitly refuses `wider.readOnly && !narrower.readOnly` — read-only can never widen to writable ([`devices/device-scopes.ts`](../../packages/identity/src/devices/device-scopes.ts)). Residual: none. | **Design** (read-only never widens) |
| **Room-scoped passport moves rooms** (a room slice retargets another room binding) | A `room` scope must match `personaId` + `roomBindingId` exactly to be contained; a different room binding is not contained and rejects ([`devices/device-scopes.ts`](../../packages/identity/src/devices/device-scopes.ts)). Residual: none from this vector by construction. | **Design** (exact room-binding match) |
| **Wildcard capability** (a passport claims "all capabilities") | There is **no** wildcard: `attenuateDeviceCapabilitiesV1` accepts only known values that are a **subset** of the approver's (`unknown_capability` / `capability_expansion_forbidden`, [`devices/device-authorization-context.ts`](../../packages/identity/src/devices/device-authorization-context.ts)); `capabilities` is a refused caller field ([`identity-validation.ts`](../../packages/identity/src/identity-validation.ts)). Residual: none. | **Design** (subset-only capability intersection) |
| **Device-add delegates recursively** (a passport grants the power to add more devices) | `identity.device.add_future` is in `DEVICE_UNAVAILABLE_CAPABILITIES` and **denies**; the add/link path is future-gated (`identity.device_key_future` = `future_gate`, [`policyMatrix.ts`](../../packages/privacy/src/policyMatrix.ts)). No passport can confer add authority. Residual: real signed delegation is Gate F. | **Policy** (`device.add_future` denied) + **Gate F** |
| **Recovery capability appears** (a passport smuggles recovery-approval authority) | `identity.recovery.approve_future` is in `DEVICE_UNAVAILABLE_CAPABILITIES` and **denies** ([`devices/device-types.ts`](../../packages/identity/src/devices/device-types.ts)); recovery is a separate future flow gated by its own review ([ADR-0013](../adr/ADR-0013-identity-firewall-architecture.md) §13). Residual: none from this vector by construction. | **Design + Policy** (`recovery.approve_future` denied) |
| **Cross-root passport** (an approver on root A authorizes a candidate under root B) | `attenuateDeviceAuthorizationScopeV1` rejects `cross_root_forbidden` and `deviceScopeContainsV1` returns false on any `rootId` mismatch ([`devices/device-scopes.ts`](../../packages/identity/src/devices/device-scopes.ts)); independent roots stay isolated ([ADR-0013](../adr/ADR-0013-identity-firewall-architecture.md) §5). Residual: none. | **Design** (cross-root rejects) |

## 3. Replay + duplication

TECH-ID-08 is **local and unsigned**, so its replay controls are **structural only** — they are **NOT cryptographic replay resistance**. Real challenge/nonce/anti-replay is Gate F.

| Attack | Why it fails / residual | Control |
| --- | --- | --- |
| **Link request reused** (one request id drives two pending links) | The module must hold **one pending request per request id** (a structural uniqueness invariant, [TECH_ID_08_PRECHECK.md](TECH_ID_08_PRECHECK.md) §4); a second pending link for the same id is rejected. Residual: **local structural** only — not a cryptographic nonce; a copy in another vault is not reached. | **Design** (one pending per request id) + **Gate F** |
| **Draft approved twice** (a passport draft is issued into two records) | **One draft per request** and **approved-once**: the draft transitions off `draft_local` exactly once (`draft_local → active_local_unverified` or `→ revoked_tombstone`, then terminal, [`devices/device-lifecycle.ts`](../../packages/identity/src/devices/device-lifecycle.ts)). Residual: local structural only. | **Design** (approved-once transition) |
| **Expired request accepted** (a stale link request is honored) | Deadline expiry is enforced structurally (process-restart invalidation + local deadline, [TECH_ID_08_PRECHECK.md](TECH_ID_08_PRECHECK.md) §4); an expired request fails closed via the current-record re-check (`assertDeviceLinkRequestCurrentV1`, mirroring [`assertDeviceAuthorizationSnapshotCurrentV1`](../../packages/identity/src/devices/device-authorization-context.ts)). Residual: local wall-clock only — **not** a signed, verifiable expiry (Gate F). | **Design** (deadline expiry, fail-closed) + **Gate F** |
| **Revoked request reactivated** (a tombstoned link comes back) | `revoked_tombstone` is **terminal**: `assertDeviceAuthorizationTransitionV1` permits no transition out of it ([`devices/device-lifecycle.ts`](../../packages/identity/src/devices/device-lifecycle.ts)). A "new" link is a new record, never a revival. Residual: terminality is **local** — a peer/offline copy is not reached (Gate H). | **Design** (terminal tombstone) + **Gate H** |
| **Passport accepted by another device** (a draft meant for candidate X is accepted by Y) | The candidate device ref must match throughout the request; `assertDevicePassportDraftCurrentV1` fails closed on any device-ref drift (mirroring the `snapshot_identity_mismatch` check in [`assertDeviceAuthorizationSnapshotCurrentV1`](../../packages/identity/src/devices/device-authorization-context.ts)). Residual: without a signature, "the right device accepted this" is asserted locally, not proven (Gate F). See §4. | **Design** (candidate-ref bound) + **Gate F** |
| **Passport copied between roots** (a draft is replayed under a second root) | A passport references exactly one root; cross-root is rejected structurally ([`devices/device-scopes.ts`](../../packages/identity/src/devices/device-scopes.ts) `cross_root_forbidden`) and independent roots are isolated ([ADR-0013](../adr/ADR-0013-identity-firewall-architecture.md) §5). Residual: local structural only. | **Design** (single-root; cross-root rejects) |
| **Old root epoch accepted** (a draft bound to a superseded authority epoch is honored) | A passport binds to one `IdentityAuthorityEpoch`; the epoch changes only through explicit root lifecycle operations and "a changed epoch invalidates stale drafts + future passports" ([`identifiers.ts`](../../packages/identity/src/identifiers.ts)). A stale-epoch draft fails closed. Residual: the epoch is a **local counter**, not a signed generation (Gate F). | **Design** (epoch-bound; stale epoch invalidates) + **Gate F** |
| **Revision rollback** (an older record revision is replayed) | Every accepted mutation is revision-checked (`IdentityLocalRevision` `expectedRevision`); a stale revision fails the optimistic-concurrency check (`DeviceAuthorizationRevisionMismatchError`, [`devices/device-authorization-context.ts`](../../packages/identity/src/devices/device-authorization-context.ts)). Residual: revision is **local** only — not tamper resistance, not distributed ordering ([`identifiers.ts`](../../packages/identity/src/identifiers.ts)). | **Design** (revision-checked) + **Gate H** |

> **Stated plainly:** the controls in §3 are **local structural** de-duplication (unique ids, one-pending, approved-once, terminal tombstones, process-restart + deadline expiry). They are **not** cryptographic replay resistance — an attacker who can copy local state to another process/vault is outside their reach. Challenge/nonce/anti-replay is **Gate F**.

## 4. Candidate-device substitution

A link request names one candidate device; the attack is to bind a *different* device (or different claims) between display, approval, and issuance.

| Attack | Why it fails / residual | Control |
| --- | --- | --- |
| **Request id points to one device but claims bind another** | The candidate `LocalDeviceRef` must match across request → draft → record; `assertDeviceLinkRequestCurrentV1` / `assertDevicePassportDraftCurrentV1` fail closed on device-ref drift, mirroring the `snapshot_identity_mismatch` guard ([`assertDeviceAuthorizationSnapshotCurrentV1`](../../packages/identity/src/devices/device-authorization-context.ts)). Residual: binding is asserted locally, not signed (Gate F). | **Design** (candidate-ref match throughout) + **Gate F** |
| **Displayed QR / payload replaced** (a MITM swaps the linking material) | **QR / transport is not implemented** — there is no wire representation to protect in TECH-ID-08 (Gate E, [TECH_ID_08_PRECHECK.md](TECH_ID_08_PRECHECK.md) §6). A future transport must carry a signed, channel-bound payload (Gate E + Gate F). Residual: **total** for any real transport until those gates ship — stated, not solved. | **Gate E** (no transport) + **Gate F** |
| **Key-slot commitments change after approval** (a slot is swapped post-review) | Key-slot commitments are **immutable after approval**: slots are empty `reserved_not_generated` placeholders holding **no** material, `algorithm: "not_selected_gate_f"` ([`devices/device-key-slots.ts`](../../packages/identity/src/devices/device-key-slots.ts)), and a slot's purpose cannot change after activation ([`devices/device-key-purposes.ts`](../../packages/identity/src/devices/device-key-purposes.ts)). Residual: there is no key material to commit yet — the invariant guards a future, not a present binding (Gate F). | **Design** (slot commitments immutable) + **Gate F** |
| **Candidate changes requested capabilities after review** (post-approval capability creep) | Capabilities are frozen at approval to the attenuated subset; a later change fails the current-record re-check and capability-attenuation guard (`capability_removed` / `capability_expansion_forbidden`, [`devices/device-authorization-context.ts`](../../packages/identity/src/devices/device-authorization-context.ts)). Residual: local structural only. | **Design** (capabilities frozen; re-checked) |
| **Root approves an incomplete request** (a partial/malformed link is issued) | Requests are exact-shape and fail closed: unknown/absent fields reject (`assertExactKeys`, content-free `IdentityValidationError`, [`identity-validation.ts`](../../packages/identity/src/identity-validation.ts)); scope + capability validation must both pass before a draft exists. Residual: none from this vector by construction. | **Design** (exact-shape, fail-closed) |

## 5. Root + approver compromise

The approver may itself be compromised, restricted, revoked, or freshly recovered. Every state that lets a bad approver mint durable authority, or that lets old approvals survive recovery, is an attack.

| Attack | Why it fails / residual | Control |
| --- | --- | --- |
| **Compromised root signs arbitrary devices** (a subverted root mass-issues) | A `compromised_suspected` / `revoked_tombstone` root is **not usable**: `assertDeviceAuthorizationSnapshotCurrentV1` rejects `root_not_usable` when `rootCompromised` or `!rootActive` ([`devices/device-authorization-context.ts`](../../packages/identity/src/devices/device-authorization-context.ts)), and `recovery_required` / `recovered_reverification_required` roots cannot act as ordinary approvers ([`identity-types.ts`](../../packages/identity/src/identity-types.ts) `LocalIdentityRootLifecycleV1`). Residual: a root compromised **before** detection could have approved — the blast-radius of a real key compromise is a Gate F property, not decided here. | **Design** (unusable root denies) + **Gate F** |
| **Compromised device adds another device** (a bad candidate enrolls a peer) | No device can enroll a peer: the add/link path is future-gated and `identity.device.add_future` denies ([`policyMatrix.ts`](../../packages/privacy/src/policyMatrix.ts), [`devices/device-types.ts`](../../packages/identity/src/devices/device-types.ts)). Residual: none from this vector by construction. | **Policy** (`device.add_future` denied) |
| **Recovered identity preserves old passports** (a restore keeps stale device authority) | Root recovery **increments the authority epoch** (`nextIdentityAuthorityEpoch`; `IdentityAuthorityEpochStateV1.reason` includes `recovery_future` / `root_rotation_future` / `compromise_response`, [`identifiers.ts`](../../packages/identity/src/identifiers.ts), [`identity-types.ts`](../../packages/identity/src/identity-types.ts)); "a changed epoch invalidates stale drafts + future passports." Old approvals go stale. Residual: epoch invalidation is a **local** counter effect, not a signed revocation (Gate F / Gate H). | **Design** (recovery bumps epoch; old approvals stale) + **Gate F** |
| **Restricted device approves wider** (a narrowed approver issues broader authority) | Attenuation-only: a `restricted_local` approver can only re-narrow ([`devices/device-lifecycle.ts`](../../packages/identity/src/devices/device-lifecycle.ts)) and `attenuateDeviceAuthorizationScopeV1` rejects any widening ([`devices/device-scopes.ts`](../../packages/identity/src/devices/device-scopes.ts)). Residual: none from this vector by construction. | **Design** (attenuation-only) |
| **Approval chain creates hidden admins** (recursive delegation manufactures authority) | There is **no delegation**: `identity.device.add_future` + `identity.recovery.approve_future` deny, no capability confers issue-authority, and each passport only narrows one approver's own scope. Residual: none — no delegation primitive exists. | **Design + Policy** (no delegation) |

## 6. Metadata + correlation

A passport is a rich correlation surface: hardware ids, models, root ids, a device graph, timestamps, and room/relationship scopes can all re-link roots, rooms, and relationships. Every leak is an attack.

| Attack | Why it fails / residual | Control |
| --- | --- | --- |
| **Passport contains hardware id / device model / OS / hostname** | A candidate ref is opaque and encodes **none** of these ([`devices/device-identifiers.ts`](../../packages/identity/src/devices/device-identifiers.ts)); `hardwareId` / `deviceFingerprint` / `attestation` are refused caller fields ([`identity-validation.ts`](../../packages/identity/src/identity-validation.ts)), and no code collects serial/model/MAC/OS. Residual: an opaque ref still exists in local memory as a handle (endpoint scope, §9). | **Design** (opaque non-hardware ref) |
| **Root id exposed to peers** (issuance leaks the approver root) | Roots are PRIVATE and never peer-facing; a passport carries no networked field (memory/null, no export/transport in TECH-ID-08, [TECH_ID_08_PRECHECK.md](TECH_ID_08_PRECHECK.md) §4/§6). Residual: local memory holds the ref→root mapping (§9). | **Design** (private root; no export) + **Gate E** |
| **Stable passport id reused across roots** (one id re-links independent roots) | Refs are per-context opaque handles that encode no root material ([`devices/device-identifiers.ts`](../../packages/identity/src/devices/device-identifiers.ts)); independent roots stay isolated ([ADR-0013](../adr/ADR-0013-identity-firewall-architecture.md) §5). Residual: the local memory holds the mapping (§9). | **Design** (per-context opaque ref) |
| **Device graph logged / exported** (the passport set leaves the device) | There is **no** export/sync/telemetry path (memory/null, [TECH_ID_08_PRECHECK.md](TECH_ID_08_PRECHECK.md) §4); summaries are **redacted** — strict modes omit ref / scope / counts / deadlines / refs / epoch ([`devices/device-types.ts`](../../packages/identity/src/devices/device-types.ts) `LocalDeviceSummaryV1`, `redacted: true`). Residual: a local caller with full-detail rights sees its own list (§9). | **Design** (redacted summaries; no export) + **Gate E** |
| **Approval timestamps expose activity** (issue/accept times reveal a pattern) | Revocation + summary results are content-free and redacted — no trusted timestamp, no remaining-device count, no deadline (`LocalDeviceRevocationResultV1` / `LocalDeviceSummaryV1`, [`devices/device-types.ts`](../../packages/identity/src/devices/device-types.ts)); errors are content-free ([`devices/device-errors.ts`](../../packages/identity/src/devices/device-errors.ts) `SAFE_DEVICE_REJECTION`). Residual: a local observer of the process sees local effects (§9). | **Design** (content-free errors + redacted audit) |
| **Room / relationship scopes reveal the social graph** (a scope discloses who/where) | Redacted summaries omit the narrower scope ids and expose at most a `scopeKind`, never `personaId` / `relationshipId` / `roomBindingId` ([`devices/device-types.ts`](../../packages/identity/src/devices/device-types.ts) `LocalDeviceSummaryV1`); a passport record carries no relationship/room title, only opaque ids ([`identifiers.ts`](../../packages/identity/src/identifiers.ts)). Residual: a full-detail local caller sees its own scopes (§9). | **Design** (redacted scope; opaque ids) |

## 7. Revocation limitations

TECH-ID-08 revocation is a **local** tombstone. The threats here are about *pretending it is remote* — treating a local revocation as global, session-killing, key-rotating, or data-deleting. These are honest limitations (Gate H).

| Attack | Why it fails / residual | Control |
| --- | --- | --- |
| **Local revocation described as remote** (revoke here implies revoke everywhere) | Revocation is a **local** terminal tombstone; the result object is honest — `remoteDevicesAffected: false`, `remoteSessionsAffected: false` ([`devices/device-types.ts`](../../packages/identity/src/devices/device-types.ts) `LocalDeviceRevocationResultV1`; the passport `LocalDevicePassportRevocationResultV1` mirrors these all-false flags per [TECH_ID_08_PRECHECK.md](TECH_ID_08_PRECHECK.md) §6). Residual: other devices are not reached — stale trust can persist elsewhere (Gate H). | **Gate H** (no remote revocation) + **Design** (honest all-false flags) |
| **Already-activated device remains usable** (revoke doesn't stop an active device) | A revoke tombstone is terminal and invalidates local snapshots (`revokedLocally: true`, `localSnapshotsInvalidated: true`), but it cannot reach a device already operating elsewhere. Residual: honest — the local flag has no wire effect (§9, Gate H). | **Design** (local terminal) + **Gate H** |
| **Stale offline client continues** (a disconnected device acts on old authorization) | No causal ordering / shared clock exists; `IdentityLocalRevision` is explicitly **not** a vector clock or synchronization ([`identifiers.ts`](../../packages/identity/src/identifiers.ts)). Residual: an offline device's view can diverge arbitrarily — disclosed. | **Gate H** + **Inherent** |
| **No device-list sync** (the local list is assumed globally fresh) | There is **no** synchronization of passport/device-auth state (device-auth revocation is under Gate H, [ADR-0013](../adr/ADR-0013-identity-firewall-architecture.md) §19); the aggregate is one local memory/null store. Residual: a device revoked elsewhere is simply not represented locally. | **Gate H** (sync deferred) |
| **Passport revoked but `DeviceAuthorizationRecord` remains usable** (revoking the passport leaves the record live) | Passport revocation and the authoritative device record are reconciled through the same terminal-tombstone + revision discipline ([`devices/device-lifecycle.ts`](../../packages/identity/src/devices/device-lifecycle.ts), [`devices/device-authorization-context.ts`](../../packages/identity/src/devices/device-authorization-context.ts)); a revoked passport must not leave an operational record behind (fail-closed re-check). Residual: correctness of this reconciliation is a **local** invariant the module must uphold, not a signed guarantee (Gate F). | **Design** (single terminal source of truth) + **Gate F** |
| **Revocation falsely claims data deletion / key rotation** (revoke implies wipe/rotate) | The result is honest: `messageKeysRotated: false`, `roomKeysRotated: false`, `deviceDataErased: false`, `cryptographicRevocationPerformed: false` ([`devices/device-types.ts`](../../packages/identity/src/devices/device-types.ts) `LocalDeviceRevocationResultV1`). No deletion or rotation is claimed. Residual: real key rotation + forensic erasure are Gate F / external — disclosed. | **Design** (honest all-false flags) + **Gate F / External** |

## 8. Attestation confusion

A passport must never be mistaken for a hardware/posture guarantee. Every path that reads a passport as attestation, or folds DevicePosture into it as a durable credential, is an attack.

| Attack | Why it fails / residual | Control |
| --- | --- | --- |
| **Passport claims a hardened device** (a passport carries a posture/attestation claim) | A passport carries **no** posture or attestation claim: the record is `hardwareAttested: false` and the summary `postureVerified: false` ([`devices/device-types.ts`](../../packages/identity/src/devices/device-types.ts)); `attestation` / `devicePosture` / `deviceSafe` are refused caller fields ([`identity-validation.ts`](../../packages/identity/src/identity-validation.ts)). Residual: none from this vector by construction. | **Design** (no posture/attestation claim) |
| **DevicePosture embedded as a permanent credential** (a one-time reading is frozen into the passport) | DevicePosture is never embedded in an identity record (identity never imports `@freelayer/rooms`), and a `devicePosture` field is refused ([`identity-validation.ts`](../../packages/identity/src/identity-validation.ts)); posture is evaluated **independently at use time** and can only tighten ([`device-posture.ts`](../../packages/rooms/src/policy-composition/device-posture.ts) `mayOnlyTighten: true`). Residual: UX must not render a past reading as a durable property — disclosed obligation. | **Design + Policy** (posture never embedded; evaluated at use time) |
| **Hardware attestation treated as identity authorization** (a "genuine device" signal authorizes) | A `DevicePostureAuthorityError` names the rejection of posture-as-authority ([`devices/device-errors.ts`](../../packages/identity/src/devices/device-errors.ts)); posture is `trustedForElevation: false`, "never identity, never authority" ([`device-posture.ts`](../../packages/rooms/src/policy-composition/device-posture.ts)). Attestation can only deny, never compensate for a missing approval. Residual: real hardware attestation is Gate F / external — absent here. | **Policy** (posture ≠ authorization) + **Gate F** |
| **Managed-bunker label creates authority** (a `managed_bunker` posture reads as an approver) | `managed_bunker` is only one posture value on an environment attribute that `mayOnlyTighten` and is never an approver ([`device-posture.ts`](../../packages/rooms/src/policy-composition/device-posture.ts)); `at_risk` always overrides higher claims, and no provider is integrated (`providerIntegrated: false`). Residual: none — a posture value never grants authority. | **Policy** (posture tightens only; provider not integrated) |

## 9. Endpoint limits

The endpoint is outside the module's trust boundary. TECH-ID-08 states this plainly rather than implying custody it does not provide. These are honest limitations.

| Attack | Why it fails / residual | Control |
| --- | --- | --- |
| **Malware steals a future passport / device key** (exfiltration from a compromised OS) | TECH-ID-08 holds **no** signed passport and **no** key bytes to steal (`authorizationProofState: "not_implemented_tech_id_08_gate_f"`, key slots hold no material — [`devices/device-types.ts`](../../packages/identity/src/devices/device-types.ts), [`devices/device-key-slots.ts`](../../packages/identity/src/devices/device-key-slots.ts)); when Gate F ships, key custody is an **external** Secure Device / Endpoint Defense concern ([ADR-0012](../adr/ADR-0012-endpoint-defense-layer.md)). Residual: total on a compromised endpoint — malware sees what the user sees. | **External** (endpoint) + **Gate F** |
| **Screenshot captures linking material** (the on-screen payload is grabbed) | There is no QR/wire payload in TECH-ID-08 to capture (Gate E, [TECH_ID_08_PRECHECK.md](TECH_ID_08_PRECHECK.md) §6); a future transport must be channel-bound + signed. Residual: screen-capture of any future material is an **external** endpoint concern — disclosed. | **Gate E** + **External** |
| **Compromised candidate changes the payload** (a subverted device alters what it accepts) | A compromised endpoint is outside the module's reach; the candidate-ref + fail-closed re-checks (§4) bound local drift but cannot defend a device that is itself controlled by an attacker. Residual: honest — endpoint integrity is external ([ADR-0012](../adr/ADR-0012-endpoint-defense-layer.md)). | **External** (endpoint) + **Design** (local fail-closed) |
| **Secure Device unavailable** (no hardened custody to fall back on) | Secure Device is a separate, externalized project (`check:no-secure-device-core-implementation`, [`device-posture.ts`](../../packages/rooms/src/policy-composition/device-posture.ts)); core makes no claim about its availability and does not depend on it for local correctness. Residual: without it, there is no hardened custody — disclosed. | **External** (Secure Device) |

## Explicitly NOT provided (read this)

**Stated plainly, without hedging:**

- **No cryptographic passport.** TECH-ID-08 produces no signature, no signed or verified passport, and performs no cryptographic operation. Every record is `cryptographicallyAuthorized: false`, `authorizationProofState: "not_implemented_tech_id_08_gate_f"`. Signed issuance + verification are **Gate F**.
- **No replay-resistant linking.** The §3 controls are local structural de-duplication (unique ids, one-pending-per-request, approved-once, terminal tombstones, process-restart + deadline expiry). There is **no** challenge, nonce, or anti-replay proof. Cryptographic replay resistance is **Gate F**.
- **No remote activation or revocation.** Issuance, acceptance, and revocation are local; the honest result flags are all false for remote/session/key-rotation/erasure/cryptographic effects (`LocalDeviceRevocationResultV1`). Distributed activation / revocation / sync is **Gate H**.
- **No hardware or posture guarantee.** A passport carries no attestation and no posture claim (`hardwareAttested: false`, `postureVerified: false`); DevicePosture may only tighten and is never an approver. Hardware attestation is Gate F / external.
- **No endpoint guarantee.** Key custody, exfiltration resistance, transport integrity, and screen-capture defense are external (Secure Device / Endpoint Defense) or absent. Memory/null retention does not stop a compromised OS, malware, backups, or crash dumps.
- **Not safe for real secrets.** Until reviewed identity/crypto (Gate F), transport (Gate E), and Secure Device integration ship, a Device Passport must not be treated as a safe carrier of authority whose exposure or forgery would cause real harm.

**And, stated as invariants:**

- **A Device Passport is not DevicePosture.** A passport is an identity-owned local approval draft; DevicePosture is a separate RoomOS environment attribute that may only tighten ([`device-posture.ts`](../../packages/rooms/src/policy-composition/device-posture.ts)).
- **A Device Passport is not attestation.** It makes no claim that a device is genuine, hardened, or uncompromised (`hardwareAttested: false`; `attestation` refused, [`identity-validation.ts`](../../packages/identity/src/identity-validation.ts)).
- **A Device Passport is not proof-of-safety.** An unsigned approval is not evidence of key custody, device integrity, or a safe environment.
- **A Device Passport is not real-world identity.** It authorizes a subordinate device slice, never a personhood or legal-identity claim ([ADR-0013](../adr/ADR-0013-identity-firewall-architecture.md) §4, §11).
- **A device is not a person.** A device authorization is a subordinate grant, never a personhood claim.
- **A passport id is not a hardware identifier.** It is an opaque per-context handle that encodes no serial / model / MAC / IMEI / advertising id ([`devices/device-identifiers.ts`](../../packages/identity/src/devices/device-identifiers.ts)).
- **A local unsigned approval is not cryptographic authorization.** It grants no operational device authority; `cryptographicallyAuthorized: false` and the authoritative record stays `origin: "device_passport_future"` until Gate F ([`devices/device-types.ts`](../../packages/identity/src/devices/device-types.ts)).
- **A QR code is only a transport representation.** No QR/wire transport exists in TECH-ID-08; a future transport carries no authority of its own and must be channel-bound + signed (Gate E + Gate F).
- **Room membership does not authorize a device.** RoomOS roles are non-approvers; identity never imports `@freelayer/rooms`, and no room capability mints a device authorization ([ADR-0013](../adr/ADR-0013-identity-firewall-architecture.md) §11).
- **Deferred Gates E / F / H.** QR / wire transport (E), signed issuance / passport signature / verification (F), and sync / remote revocation (H) are all out of scope for TECH-ID-08.

## Top threats — indicative severity / likelihood and resolving control

Severity and likelihood are **indicative pre-implementation judgments**, not measurements — they rank where design and test attention are most needed. "Resolved / bounded by" names the control (Design / Policy / Gate) that carries each item; none is claimed fully solved.

| # | Threat | Severity | Likelihood | Resolved / bounded by |
|---|--------|----------|------------|-----------------------|
| 1 | A passport is treated as valid authority without an authentic exact-scope root approval (UI flag, RoomOS role, DevicePosture, label, test issuer, generic patch) — (1) | Critical | Low | **Design + Policy** (no producible authorized/signed state; issuance future-gated; posture/role never approve; no generic patch; guard + tests) |
| 2 | A passport grants more scope/capability than the approver holds (root-wide, read-only→writable, cross-root, wildcard, delegation, recovery) — (2) | Critical | Low | **Design** (attenuation-only scope + subset-only capability; `device.add_future` / `recovery.approve_future` denied) + **Gate F** |
| 3 | A draft/link is replayed or duplicated (reused request, double-approve, expired/revoked reactivated, cross-root/epoch replay, revision rollback) — (3) | High | Medium | **Design** (local structural: unique ids, one-pending, approved-once, terminal tombstone, epoch/revision checks) + **Gate F** (no crypto replay resistance) |
| 4 | A different candidate device (or altered claims) is bound between display, approval, and issuance — (4) | High | Medium | **Design** (candidate-ref bound; fail-closed re-check; slot commitments frozen) + **Gate E/F** (transport/signature absent) |
| 5 | A compromised, restricted, revoked, or freshly recovered approver mints or preserves durable authority — (5) | Critical | Low | **Design** (unusable root denies; attenuation-only; recovery bumps authority epoch → old approvals stale) + **Gate F** |
| 6 | A passport / device graph leaks hardware, model, root id, timestamps, or the social graph — (6) | High | Low | **Design** (opaque non-hardware refs; redacted summaries; content-free errors; no export) + **Gate E** |
| 7 | Local revocation mistaken for remote/session-killing/key-rotating/data-deleting; stale device trusted elsewhere — (7) | Medium | Medium | **Gate H** (no remote revocation/sync) + **Design** (honest all-false flags) |
| 8 | A passport read as attestation / posture guarantee, or DevicePosture embedded as a durable credential — (8) | High | Medium | **Design + Policy** (no posture/attestation claim; posture tightens only, evaluated at use time) + **Gate F** |
| 9 | Future passport/key stolen or linking material captured on a compromised endpoint; Secure Device unavailable — (9) | High | Medium | **External** (Secure Device / endpoint) + **Gate E / F** |
